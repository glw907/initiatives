## Calls this plan makes

The design leaves these to the builder. A reviewer may contest any of them.

- **Grant map shape.** `secrets/proton-grants.tsv`, tab-separated, one header line, columns `agent`, `vault`, `role`, `expires`. Twelve rows: `pavilion-claude` and `thinkpad-claude` as editor on `Infrastructure`, `Projects`, `ASC`, `Test accounts`, and `Age key`, with expiry 2027-01-20 and 2027-02-02 (`bluefin-admin.md:355`); `pavilion-scripts` and `thinkpad-scripts` as viewer on `Age key`, with `expires` set to `keyring`, since `ws-pass-key --store` records theirs (`ws-pass-key:71-72`).
- **What each host checks.** `check-drift` compares only this host's rows (`<host>-claude`, `<host>-scripts`) with `pass-access`, because a token is readable only on the host whose keyring holds it. The expiry leg reads every Claude row in the map, so either host warns for both, and keeps today's keyring check for this host's scripts agent (`check-drift:89-110`). The thresholds are today's: a warning inside 30 days, a failure once past (`check-drift:78`).
- **A failed sign-in warns.** When `pass-access` can't sign in, the grant leg warns and names the throttle (`bluefin-admin.md:358-360`), because the weekly timer (`check-drift.timer`) would otherwise fail on a throttle. A row missing or extra fails.
- **A skip for repeat runs.** `PASS_ACCESS_SKIP=1` makes the grant leg print one warning that it skipped and sign in to nothing, so a session that reruns `check-drift` doesn't spend sign-ins. The monthly review and the first run after merge (After merge 4) never set it.
- **Item shares stay anonymous.** `pass-access` prints an item share as `(item share)` in the vault column, never its title, so the public fixture and the transcript carry no item title. The map holds no item rows, so any item share fails the leg.
- **Overrides.** `PASS_ACCESS` (the design's name) points `check-drift` at a stub. `PASS_GRANTS` points it at a test map, since the expiry cases need dates relative to today. `pass-access` takes `CLAUDE_PASS` and `WS_PASS_KEY`, as `check-drift` does (lines 81, 117).
- **The title lint's home.** `check-drift --titles` reads the five Claude vaults through `claude-pass item list`, 150 seconds apart (`bluefin-admin.md:358-360`), applies the rules of `~/.local/state/credential-hygiene/lint.py`, and reads its exceptions from `${PASS_TITLE_EXCEPTIONS:-$HOME/.local/state/credential-hygiene/title-exceptions.txt}`, which T4 writes from `lint.py`'s `LOWER_OK`. A missing file runs with no exceptions and says so. It writes each finding to `${PASS_TITLE_FINDINGS:-$HOME/.local/state/credential-hygiene/title-findings.tsv}` (mode 600) and prints only the count and that path, so no title reaches a transcript, a hand-over, or a public PR. Four 150-second gaps pass the Bash tool's 600-second foreground limit, so every live run goes through `run_in_background`. The monthly model review runs it (fact 6).
- **`pass-sitting`'s input.** A JSON-lines file in the shape of the apply scripts' `ops2.jsonl`, one operation per line: `move`, `rename`, `note`, `trash`, `grant`, `revoke`, and `audit`. No flag is a dry run that signs in to nothing; `--apply` signs in once. Its session directory is `$XDG_RUNTIME_DIR/pass-sitting.XXXXXX`, which T1 adds to the hook's session names.
- **Allow rules mirror `claude-pass`.** One `permissions.allow` rule per verb `claude-pass` runs (`claude-pass:44-54` plus T2's `share list`), and `Bash(pass-access)`, so a rule never admits a verb the script refuses. `pass-sitting` gets no rule, and no deny rule: the hook alone refuses it (design, "Calls the session made").
- **CLAUDE.md nets zero lines.** The file is at its 200-line cap (`wc -l` 200), which the gate enforces: `scripts/check.sh:85` runs `claude-context-budget` on it, and `claude-context-budget:22` sets `CLAUDE_MD_LINE_CAP` to 200. The skill pointer and "never run `pass-sitting`" replace stale text in the Secrets bullets (lines 103-116) and the Email bullet (lines 122-124); nothing is appended.
- **When the renames happen.** The test account item is renamed in T6, since nothing reads it by title in code. The age key item is renamed after merge (After merge 6), once both hosts run the `ws-pass-key` that reads both titles. A rename pass A can't make goes to Geoff in pass A's closing packet as a `pass-sitting` file, never to pass C.
- **The stale-name scan.** End-to-end check 4's scan is written in T5 as `~/.local/state/credential-hygiene/stale-scan.sh`, with its patterns (the retired vault names and the old restore-item titles) and its history allowlist (paths that carry a `YYYY-MM-DD` date). Pass C runs it over the other repos.
