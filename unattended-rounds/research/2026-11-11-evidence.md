`glw907/workstation` and `glw907/cairn-cms` both delete a head branch on merge (`gh api repos/<repo>`,
`delete_branch_on_merge: true`), so GitHub retargets a stacked pull request after its parent
merges. `merge <id>` runs the next merge at once and doesn't wait for that.

## Anthropic guidance on the round as the unit

Geoff ruled on 2026-11-11 that the round becomes the workstation's basic unit "unless anthropic
best practice suggests that's a bad idea". One Sonnet subagent fetched 14 Anthropic pages that day
and quoted them for and against. This session then checked each sentence marked "checked" against
the live page with a fixed-string search. The headless, scheduled-tasks, and routines pages were
not fetched.

For the round:

- "the next iteration of the coding agent was then asked to work on only one feature at a time"
  (checked), <https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents>. A
  pass is one unit of work in one fresh session.
- "consider starting with a brand new context window rather than using compaction. Claude's latest
  models are extremely effective at discovering state from the local filesystem.",
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices>.
- "Before a run goes unattended, make sure it knows what done looks like, can check its own work,
  and can only touch what it should. Give it a cap on turns or spend, and have a person approve the
  result at the end." (last clause checked), <https://code.claude.com/docs/en/best-practices>. The
  round has a usage ceiling, a cap of twice its planned minutes, and Geoff's packets at the end.
- "stop after two or three automatic continuations on the same task rather than repeating them
  indefinitely, so that a run that is genuinely stuck ends and can be reviewed" (checked),
  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5>.
  Standing answer 11 takes its relaunch cap from this.
- "A workflow script holds the loop, the branching, and the intermediate results itself",
  <https://code.claude.com/docs/en/workflows>. The conductor's order table is a plan held outside
  the model's turn-by-turn judgment in the same way.

Cautions:

- "we recommend finding the simplest solution possible, and only increasing complexity when
  needed" (checked), <https://www.anthropic.com/engineering/building-effective-agents>.
- "In a run you started before going to bed, nobody tells it, and you find out the next morning
  that it spent the whole night building on the wrong assumption." (checked),
  <https://code.claude.com/docs/en/best-practices>.
- "Claude declares victory on the entire project too early." (checked), the harnesses page above.
- "Running several sessions or subagents at once multiplies token usage." (checked),
  <https://code.claude.com/docs/en/agents>.
- "a fresh subagent first has to gather context your conversation already had, so it can end up
  *slower* than doing the task where you are" (checked), the best-practices page. A fresh planner
  for each pass pays this cost, and the first pilot round measures it.
- "For sequential tasks, same-file edits, or work with many dependencies, a single session or
  subagents are more effective." (checked), <https://code.claude.com/docs/en/agent-teams>. The
  sentence compares agent teams with a single session. A round uses no team.
- "Letting a team run unattended for too long increases the risk of wasted effort." (checked), the
  agent-teams page.

Built-in features checked for an equivalent of a round, with none found:

| Feature | Page | Why it isn't a round |
| --- | --- | --- |
| Agent view, `claude --bg` | <https://code.claude.com/docs/en/agent-view> | It shows "Needs input: Claude is waiting on something only you can provide" (checked) for a parked session. It orders nothing. The round is built on it |
| Workflows | <https://code.claude.com/docs/en/workflows> | "No mid-run user input", and "For sign-off between stages, run each stage as its own workflow" (both checked). Its subagents are not full sessions |
| Agent teams | <https://code.claude.com/docs/en/agent-teams> | "Experimental and disabled by default", and the page advises a single session for sequential work |
| `/goal` | <https://code.claude.com/docs/en/goal> | "One goal can be active per session." It holds one session to a condition and drives no second session |
| A `claude -p` shell loop | <https://code.claude.com/docs/en/best-practices> | It orders fresh runs and parks nothing |
