# Unattended rounds: evidence

Measured on pavilion on 2026-11-11 by the initiatives session that wrote the design. Each table
names its source and method. The classifications are keyword matches on free text, so read each
count as approximate.

working block is the time between a job entering the `working` state and leaving it. Blocked hours
sum the time jobs spent in a non-working state, sorted by keywords in the state's `detail` text.

| Measure | Value |

| Longest working block per job, median | 1.10 hours |
| Longest working block per job, ninth decile | 5.70 hours |

| Blocked: usage limit | 194 hours |

The usage-limit hours come from three sessions that each waited about 64 hours from 2026-11-04 to
the weekly reset on 2026-11-06 at 23:00 America/Anchorage.

A rerun of the `/usage` read on 2026-11-11 also printed suggestions for the last 24 hours (7,684
requests in 69 sessions on this machine): "87%  Give "general-purpose" subagents a cheaper model",
"49%  Run fewer sessions at once · up to 15 at once", and "44%  Stop sessions you no longer need ·
some ran 8 hours or more". It marks the figures "Approximate · sessions on this machine only ·
shares overlap".

The busy check reads every row of `claude agents --json` whatever its state
(`bin/.local/bin/claude-worktree-busy:63-65`), and three `done` sessions were listed on
2026-11-11. A finished or parked executor therefore keeps its repo busy until `claude stop <id>`
removes its row.

Not probed: whether a session paused by a usage limit resumes at the reset without `/goal`. The
`/goal` page says a goal pauses on a usage limit and resumes when the limit resets
(<https://code.claude.com/docs/en/goal>).

## Anthropic guidance the design draws on

- Best practices for Claude Code, <https://code.claude.com/docs/en/best-practices>: "Interview me
  until you could write the spec, then write it to SPEC.md."; build in a fresh session; "A reviewer
  that's asked to find problems will always find *something*."
- Common workflows, <https://code.claude.com/docs/en/common-workflows>: for a run with nobody
  present, "be explicit about what success looks like ... it can't ask clarifying questions."
- Effective harnesses for long-running agents,
  <https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents>.
- How we built our multi-agent research system,
  <https://www.anthropic.com/engineering/multi-agent-research-system>: "Each subagent needs an
  objective, an output format, guidance on the tools and sources to use, and clear task
  boundaries."

  models."

  <https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5>:
