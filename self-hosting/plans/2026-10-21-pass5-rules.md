# Pass 5 (ward): permission rules

The narrow allow and deny rules Pass 5 needs, for the conductor to land in a workstation PR on branch `self-hosting-pass5-rules` once Geoff asks for them in the plan sitting. The planner wrote them here because the auto mode classifier refused its own edit of the settings source as self-modification (2026-10-21 about 06:00 UTC). The workstation's auto mode text admits that edit "when Geoff asked for that rule in the session", which the sitting provides.

## Why each rule exists

On 2026-10-21 at 04:01 UTC the classifier denied Pass 3's `cd .../photos; bash cloudflare/r2.sh --apply 2>&1 | tail -15; ...` (servers#7, `## Stop`). The allow rule `Bash(cloudflare/r2.sh --apply)` was in place, but a Bash rule "matches the command text Claude writes, after Claude Code splits compound commands and strips wrappers. It doesn't match the same program invoked in a different form" (<https://code.claude.com/docs/en/permissions>, "What a Bash rule doesn't match"), and `bash` is not one of the stripped wrappers ("`timeout`, `time`, `nice`, `nohup`, and `stdbuf`, plus the shell builtins `command` and `builtin`"). So the classifier decided the call. Two fixes follow. The executor prompt requires the exact rule form, one live script per Bash call. And each existing script rule gains its `bash` form, so one slip doesn't stop a run.

## The patch

In `claude/.claude/settings.json`, append to `permissions.allow` after the `secret-receive` rule:

```json
"Bash(bash scripts/dry-run.sh)",
"Bash(bash scripts/dry-run.sh *)",
"Bash(bash infra/provision.sh --apply *)",
"Bash(bash infra/provision.sh snapshot *)",
"Bash(bash scripts/apply.sh * --apply)",
"Bash(bash scripts/restore-drill.sh *)",
"Bash(bash cloudflare/dns.sh --apply)",
"Bash(bash cloudflare/r2.sh --apply)",
"Bash(bash cloudflare/access.sh --apply)",
"Bash(bash cloudflare/deploy.sh monitor)",
"Bash(bash cloudflare/deploy.sh mta-sts)",
"Bash(cloudflare/access.sh --token ward)",
"Bash(scripts/archive.sh *)",
"Bash(scripts/imap-sweep.sh *)",
"Bash(brew install stalwartlabs/tap/vandelay)",
"Bash(vandelay import jmap *)",
"Bash(vandelay import caldav *)",
"Bash(vandelay import carddav *)",
"Bash(vandelay inspect *)",
"Bash(vandelay export --url https://ward.907.life *)",
"Bash(curl --url smtps://smtp.gmail.com:465 *)",
"Bash(curl --url smtps://ward.907.life:465 *)"
```

Append to `permissions.deny` after the last `npx wrangler` rule:

```json
"Bash(vandelay * --prune)",
"Bash(vandelay * --prune *)",
"Bash(imapsync)",
"Bash(imapsync *)"
```

Deny rules win over allow rules ("Rules are evaluated in order: deny, then ask, then allow"), so `vandelay export --url https://ward.907.life ... --prune` is refused though its allow rule matches. The `curl` rules put the URL first because "Claude Code matches everything before the first `*` as written", and a rule with a `*` before the rest of the command draws a startup warning.

## The proof

After the PR merges and `claude-tooling-sync apply` runs, the conductor proves the rules in a `claude -p --permission-mode dontAsk` session, where anything a rule doesn't allow is refused and the classifier plays no part. It runs from a scratch directory under its job's `tmp` that holds stub scripts at each rule's path (`infra/provision.sh`, `scripts/apply.sh`, `scripts/restore-drill.sh`, `scripts/dry-run.sh`, `scripts/archive.sh`, `scripts/imap-sweep.sh`, and `cloudflare/{dns,r2,access,deploy}.sh`, each mode 755) and a stub directory first on `PATH` for `brew`, `vandelay`, `curl`, and `imapsync`. Every stub appends its argv to one log file and exits 0, so nothing reaches an account.

Pass when the log shows each allowed form ran, including `bash cloudflare/r2.sh --apply` and `cloudflare/access.sh --token ward`, and shows no entry for `imapsync --host1 x`, `vandelay export --url https://ward.907.life --prune x`, or `cloudflare/access.sh --token orpheus`.
