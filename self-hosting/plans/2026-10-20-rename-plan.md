## Order of the live steps

Four rules set the order, and each task's acceptance checks the one it touches.

- **Reachable.** The box keeps key-based SSH throughout. `orpheus` gets its DNS records before any script reaches it by that name, and `media` resolves through every step (A records, then a CNAME to orpheus). Direct SSH from the main loop uses `ssh -o BatchMode=yes geoff@media.907.life`, which the live permission rules allow, until the workstation PR that names orpheus merges. The old tunnel keeps a connector until Geoff's sign-in through the new one is proven.
- **No false alert.** The monitor Worker learns the new keys before the box uses them (R4). The heartbeat check moves from `media` to `orpheus` within minutes of the first orpheus heartbeat, inside the 45-minute missing-heartbeat window, and the snapshot check moves once the new bucket holds a snapshot. The snapshot check moves to a new label rather than repointing the old one, because the old label's baseline of seen snapshots would read the new bucket's contents as vanished.
- **Scripts before the live rename.** The renamed scripts land on the branch first (R1, R2), but nothing runs them against Hetzner until R5 has renamed the live resources, because `provision.sh --apply orpheus` against an unrenamed project would create a second server.
- **Proof before each deletion.** The new repository takes a backup and passes the drill before the old buckets and tokens go, the new tunnel carries Geoff's sign-in before the old one goes, and every old secret name goes last, once nothing reads it. Each deletion is its own task (R11 to R15).

## Stops and standing answers

From the base plan, unchanged: the classifier row (never retried, recorded, and the item named in "Not checked"), the count cap as a loop guard, and the four-times task extension.

| Situation | Answer |
|---|---|
| A lock rule on an old bucket, or Pass 3 launched | Stop for `conductor-servers`: R13 cannot delete a locked bucket, and the design's premise fails. |
| A `heartbeat_missing` or `snapshot` condition opens during R4 to R10 | A false alert, so trace its cause, fix it, and record the fix under `## Decisions`. A cause that can't be traced is a stop. |
| The pre-flight token has expired before R14 | Leave R14's narrowing and deletions owed in the PR body with the exact calls; the conductor asks Geoff for a fresh token at the packet. Not a stop. |
