## Blockers

1. **The rejection back-out can't run, and the timer would keep the rejected script live** (plan:109, plan:82). `main` has no `roles/mail-filters/` on a rejection. `scripts/apply.sh:124-126` only replaces `/opt/servers/{base,roles}`, so the helper, the timer, and `/etc/servers/mail-filters/accounts` stay behind, and the timer keeps running `install geoff`. `install` with an empty accounts file deactivates nothing, so the runbook's off switch at plan:82 is false. *Fold*: a `deactivate ACCOUNT` verb (`SieveScript/set` with `onSuccessDeactivateScript: true`, in its own request); `install` deactivates the managed script on any `accounts.json` mailbox the accounts file doesn't list, with a test; write the back-out in full as the Bulwark plan does (`undo geoff <manifest>`, `mail-filters deactivate geoff`, `systemctl disable --now mail-filters-refresh.timer`, remove the units, the helper, the data, and `/etc/servers/mail-filters`, `daemon-reload`, then apply ward from `main`).
2. **The GTUBE probe case can never pass, which blocks enabling `geoff`** (plan:90, plan:120). Stalwart runs the spam filter only for unauthenticated sessions: the default `enable_spam_filter` is `is_empty(authenticated_as)` (`crates/registry/src/schema/structs_impl.rs:28905-28907`, used at `crates/smtp/src/inbound/data.rs:525-529`), and `roles/stalwart/plan.ndjson` doesn't override it. A GTUBE sent from `probe2` over authenticated submission is never scored and files as personal. *Fold*: send the spam case unauthenticated to `smtp://ward.907.life:25` from the workstation, as `docs/cutover-log.md:87` did (`probe.907.life`'s MX is ward, `plan.ndjson:8`). Send the other five over authenticated 587. Header `From` can be forged on submission, since `must_match_sender` checks only the envelope (`crates/smtp/src/inbound/mail.rs:235-251`). Write both send commands in full.

## Majors

3. **`undo` breaks once `--prune` deletes the old folders** (plan:61-62, 93, 109). The manifest holds folder ids; step 5 prunes the emptied folders right after the re-sort. *Fold*: record each folder's path with its id; `undo` recreates a missing path through the `Mailbox/set` create chain `move` uses; T3 tests undo after prune.
4. **OWNER FORK: one active script per account, shared with other writers** (plan:76, plan:48). Stalwart keeps one `ActiveScriptId`, and `VacationResponse/set` with `isActive` makes the vacation script active, switching off the previous one (`crates/jmap/src/vacation/set.rs:281-295`). Bulwark's filters UI writes "the active non-vacation script, else the first one" (`bulwarkmail/webmail lib/filters/account-filters.ts:21, 107-111`). A timer that updates only on a hash change leaves a switched-off script off, and when data changes it switches off a vacation reply or overwrites a Bulwark edit. *Options*: (a) the managed script is authoritative: each run checks it's active and matches, re-activates it, but doesn't while the vacation script is active (it logs, and filtering pauses); the runbook says filters change only through the data files. (b) as (a), with `include :personal :optional "vacation"` in the template, which needs runner support. (c) the timer yields to any foreign edit and alerts. *Recommendation*: (a).
5. **The ward hold line is never set but is cleared after merge** (plan:89-91, plan:107). *Fold*: before T7 step 2, send `conductor-servers` the hold line ("ward runs branch mail-filters until it merges"), as the Bulwark plan's T7 does.
6. **Live commands aren't written in full, and two don't exist as stated** (plan:90-94). (a) The submission send has no command, credential source, or port. (b) `stalwart-jmap` has no verb that reads a message's folder: `find` prints ids, `show` prints counts (`roles/stalwart/stalwart-jmap:4-9`). (c) Step 4's `restic snapshots --no-lock` points at the orpheus restore kit with placeholder credentials (`docs/runbook.md:144-158`); ward lists backups with `sudo server-restore list` (`docs/runbook.md:104-108`). (d) `resort --apply` and `folders geoff --prune` lack their ssh and sudo form. *Fold*: spell out each send (curl smtp/smtps, password from `secrets_load STALWART_PASSWORD_TEST2` through a `-K` stdin config, never argv); read folders with `ssh -o BatchMode=yes geoff@ward.907.life sudo mail-filters export probe` filtered by Message-ID plus `mail-filters folders probe`; read the snapshot with `sudo server-restore list` and `backup-status.json` `last_ok_at`; write the full `ssh ... sudo /usr/local/sbin/mail-filters move geoff < plan` and `--prune` forms.
7. **Runner parity covers extensions only, and the size limit has no standing answer** (plan:72, 74, 117). Stalwart builds user scripts with these limits (`crates/common/src/config/mailstore/scripts.rs:48-95`): script 102400, strings 4096, nested tests 15, 128 local variables, 5000 CPU cycles, `max_header_size` 1024, and all capabilities plus Expressions minus `disable_capabilities` (empty by default, `structs_impl.rs:36813-36845`, unset on ward). T2 points at the wrong directories. A runtime error makes Stalwart continue and fall back to the Inbox when no keep or fileinto ran (`crates/email/src/sieve/ingest.rs:502-520`); the runner has no error case. The fallback extension list lacks `spamtestplus` (needed by `:percent`) and `special-use`. *Fold*: the runner copies `scripts.rs:55-95` with its limits and maps a runtime error to an Inbox verdict; T5 measures the rendered size and the largest per-message instruction count; a standing answer for over-limit (keep every contact, trim Sent Items correspondents to recent years until it fits, record the cut); fix the fallback list.
