Every cairn command, in the installer's language

The commands that print and exit, redrawn with the installer's roles, marks, and grid. They take no stage rail and no full screen. The installer's own screens are on the companion page, flow.html.

The language

One table of roles and marks, one grid. The installer already uses most of it. Every frame below is drawn from these pieces and nothing else.

Reports

health, doctor, and logs move onto the installer's grid. The ruled headings give way to the installer's bold titles, everything sits on the two-cell margin, and details line up on column 20. The verdict words, the section order, and the closing verdict line stay.

Lists and receipts

sites, auth, adopt, and new status print plain tab-separated text today, on a terminal as well as a pipe. On a terminal they take a title, a table or label rows, and a one-line receipt. A pipe keeps the tab-separated lines it has now.

Help and errors

The two places every command passes through. Help keeps the layout its library draws and takes the shared inks, so it stops disagreeing with the reports about light and dark. An error on a terminal gets the failing mark and the fix arrow. Today it is unstyled text.

Without colour, and without Unicode

The same frame twice. Meaning never rides on colour alone, so the report reads the same in one ink. A terminal that cannot show the marks gets the ASCII tier, and a pipe gets the plain body it has today.

What is a stand-in here. These are drawings, so the real terminal will differ in font. The report wording is today's, moved onto the grid. The doctor check names, the auth check permission names, the help descriptions, the receipts, and the error lines are placeholder wording for an editor to write to the copy standard. The held mark is a proposal: if it does not paint one cell wide in a real terminal, held keeps the open circle. The help frame is drawn from the rules of the library that draws it and not captured from a run.
