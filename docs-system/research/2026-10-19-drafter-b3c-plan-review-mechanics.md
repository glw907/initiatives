## Findings, ranked by consequence

1. **Blocker, correctness.** `plan.md:466`, `:478`, `:497-498`. The fix steps use the bare installed `drafter check`. It loads config (`check.go:56` `config.Load`) and the lock (`internal/blueprint/check.go:360` `lockEntries`); config decode is strict (`file.go:98-106`) and the lock decodes with `KnownFields` (`lock.go:60`). After B3c.5 commits `brief_path` and P1 commits `blocked`, B3's installed `drafter` exits 2 in the cairn worktree and every `b3c-fix-*` worktree. A zero-context fix agent (whose blueprint skill also says `drafter check`) may "fix" `drafter.toml`. Fold: resolution 8 and each fix prompt name `$B3C_DRAFTER check <its blueprint>` by absolute path and forbid bare `drafter`. B3c.4's reshape runs before B3c.5, so the installed binary is fine there.
2. **Blocker, correctness.** `plan.md:393`. Each reshape worktree branches from the conversion commit holding all seven unreshaped blueprints. On the probe clone unscoped `drafter check` prints `524 errors, 61 warnings`; `drafter check blueprints/docs/extend/debug-your-site.blueprint.yaml` prints `42 errors, 5 warnings`. An agent told to reach 0 errors may edit a sibling, breaking disjointness. Fold: "runs `drafter check <its blueprint path>` until 0 errors"; the session's unscoped check after merging stays.
3. **Major, correctness.** `plan.md:504-505`, `:513-514`. Stall-rule mechanics are wrong. A cancelled batch classifies `ActionResubmitThenStop` (`internal/batch/classify.go:11`, `pipeline/handle.go:147-150`): while drafter polls, the first cancel resubmits as a new batch; only a second cancel halts with `StopInfrastructure`. drafter has no signal handling (no `NotifyContext`); killing it leaves state `running`, the batch live, and reservations open, raising `open.worst` permanently (as B3's $1 did). The halted run then trips Merge order step 1's `grep -l '"stopped"'`. Fold: (1) cancel twice through the API, or cancel then wait for the halt; (2) record the stopped run id and its `open.worst` in STATUS; (3) rerun remaining pages with `--sync` as a new run; (4) at close list the pass's own stopped runs as abandoned and read the merge-order grep against that list.
4. **Major, correctness.** `plan.md:266-274`. The bar paragraph conflicts with the change read's Nit rule: in a change read, findings on order, pace, heading form, field placement, or a `use` restating its fact are always non-blocking "Nit:" and "A Nit never makes the verdict fix" (chain about `:2360`, `stock/prompts.js:148+`). Many whole-read blocking findings are those classes, so a bar read could accept with an unfixed one (false convergence; Check 1 still passes). Fold: the bar paragraph says a "Still open:" finding blocks whatever its class, overriding the Nit rule; add one B3c.2 golden row and one B3c.3 test row asserting that sentence.
