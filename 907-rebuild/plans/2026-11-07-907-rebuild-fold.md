## Probes

Each mechanism the fold introduces, with its source.

- **`env -i` launch with a separate home.** A local probe ran on 2026-11-07: `env -i HOME=<scratch> LANG=C.UTF-8 TERM=xterm-256color PATH=/var/home/glw907/.local/share/mise/installs/node/lts/bin:/home/linuxbrew/.linuxbrew/bin:/usr/bin:/bin bash -c '...'`. It printed `v26.13.0`, `11.20.0`, `gh version 2.103.3`, `git version 2.56.0`, and `2.1.319 (Claude Code)`, then "You are not logged into any GitHub hosts", with environment names `HOME LANG PATH PWD SHLVL TERM _`. Credentials follow the home: "On Linux, credentials are stored in `~/.claude/.credentials.json`" (docs/en/authentication).
- **Ancestor loading, the reason for `/var/tmp`.** "Claude Code loads `CLAUDE.md` and `CLAUDE.local.md` from your current working directory and every directory above it" (docs/en/memory). It counts "a `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` in your working directory or any directory above it" (same page). It "loads project skills from `.claude/skills/` in the directory where you start it and in every parent directory up to the repository root" (docs/en/skills). tmpfiles: `q /var/tmp 1777 root root 30d` (`systemd-tmpfiles --cat-config`).
- **`claudeMdExcludes` (considered, not used).** "Patterns are matched against absolute file paths using glob syntax", and "Exclusions apply only to user, project, and local memory files" (docs/en/settings-reference). It doesn't cover ancestor skills, so relocation was chosen.
- **Absolute-path deny rules.** "`//path` | Absolute path from filesystem root | `Read(//Users/alice/secrets/**)`", and "A pattern like `/Users/alice/file` isn't an absolute path" (docs/en/permissions). On symlinks: "a deny or ask rule written through a symlinked directory ... also applies at the directory's real location", so both `/var/home` and `/home` spellings are written and probed.
- **The `Read(!...)` negation.** "Claude Code reads a `!` pattern relative to the current directory even when `/`, `~/`, or `//` follows the `!`, so the pattern can't reach a rule anchored with one of those prefixes" (docs/en/permissions). Not used.
- **Sandbox read rules.** "When read rules overlap, the rule with the narrower path applies", with the example `"denyRead": ["~/"]` and `"allowRead": ["~/projects"]`. Also: "A `denyRead` entry doesn't stop the Read tool" (docs/en/sandboxing). Path prefixes: "`/` | Absolute path from filesystem root" and "`~/` | Relative to home directory" (docs/en/settings-reference).
- **`excludedCommands` (considered, not used).** "Every command in the call has to match", "a redirect to a file, a `cd`, or a command substitution such as `$(...)` keeps the whole call sandboxed", and "An excluded command runs with your full access" (docs/en/sandboxing). Setup moved to Geoff's shell instead.
- **Sandbox limits.** "a sandboxed command's `localhost` is private to that command"; "Anything that isn't TCP: UDP ... can't leave the sandbox"; "Chromium exits with `No usable sandbox!`" and "start the browser with `--no-sandbox`" (docs/en/sandboxing).
- **Node and the proxy.** "When enabled, Node.js parses the `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY` environment variables during startup, and routes requests through the specified proxy", added in v24.0.0 (`nodejs/node` `doc/api/cli.md`). It is set only if T1's fetch fails.
- **`dontAsk` with allow rules.** "Auto-denies every call that would otherwise prompt ... tools pre-approved via `/permissions` or `permissions.allow` rules" still run (docs/en/permissions). "Deny and ask rules apply when any subcommand matches them" (same page). Also from that page: a rule "isn't a security boundary around the program". On auto mode: "When repeated blocks reach a threshold, the action doesn't run and Claude keeps working", and "broad allow rules that grant arbitrary code execution are dropped: ... Package-manager run commands" (docs/en/permission-modes).
- **`disableClaudeAiConnectors`.** "`true`: Claude Code neither fetches nor connects those connectors" (docs/en/settings-reference).
- **`syncClaudeAiSkills`.** "`false`: Claude Code stops downloading synced skills and stops loading the ones already in `~/.claude/skills/synced/`", with scope "User, local, or managed" (docs/en/settings-reference).
- **The Bash timeout variables (refused).** "`BASH_MAX_TIMEOUT_MS` | Maximum timeout the model can set for a foreground Bash ... (default: 600000, or 10 minutes)" (docs/en/env-vars). Not set, since setup no longer runs in the Bash tool.
- **Headless flags.** "`--session-id` | Use a specific session ID for the conversation (must be a valid UUID)", and `--resume` resumes "by ID" (docs/en/cli-reference). "A `-p` session shows no workspace trust dialog" (docs/en/headless). `mcp_servers` appears in `system/init` (same page).
- **Setup is a terminal task.** "for someone who is comfortable pasting a command into a terminal" (`create-your-site.md:5`). "A run that can't ask, such as `--yes` without `--email` or a script with no terminal, stays declined" (`own-your-domain.md:89`). "With `--yes`, with output redirected, or under CI, both waits park ... exit `0`" (setup README:462). On non-TTY, the sign-in link "is not printed to this non-interactive output" (`open.mjs`). Under `--yes` without the env token, the error is "This run is not interactive, so it cannot open a browser" (`prefill.mjs`). The state path is `process.env.CAIRN_STATE_DIR ?? path.join(homedir(), '.config', 'cairn', 'sites')` (`state.mjs`).
- **The setup token's keys and TTL.** `CHAPTER2_BUILDS_PERMISSION_KEYS = [...PREFILL_PERMISSION_KEYS, { key: 'workers_ci', type: 'edit' }]` (`prefill.mjs`). Cloudflare: "API tokens allow restrictions for client IP address filtering and TTLs" (developers.cloudflare.com/fundamentals/api/how-to/create-via-api).
- **How R2 objects get listed.** "GET/accounts/{account_id}/r2/buckets/{bucket_name}/objects", with `cursor`, `per_page`, and `prefix`, returning `key` and `size` (developers.cloudflare.com/api, R2 objects list). `wrangler r2 object get --help`: "`--remote` Interact with remote storage". `wrangler d1 export --help`: "`--remote` Export from a remote D1 database". "To delete an R2 bucket, it must be completely empty" (developers.cloudflare.com/r2/reference/consistency).
- **The audit's gating flag and suppression.** "`Usage: cairn-audit [--config <path>] [--rule <id>]... [--fail-on error|advisory] [--help]`" and "Suppress one finding with a comment above it: cairn-audit-disable-next-line" (`src/lib/audit/config.ts:332`, `:341`).
- **DMARC on an onboarded zone.** `ensureSendingDomain` returns the existing entry and creates nothing (`email.mjs:94`). Live DNS on 2026-11-07 answers `cf-bounce.907.life` (three Cloudflare MX records and SPF) and `_dmarc` `"v=DMARC1; p=none; rua=mailto:dmarc-reports@907.life"`, matching `servers/cloudflare/dns/ward:18`.
- **GitHub's rename redirect.** "all existing information ... is automatically redirected to the new name". If a new repository takes the old name, "redirects to the renamed repository will no longer work" (docs.github.com, renaming a repository).
- **`gh` scopes.** "The minimum required scopes for the token are: `repo`, `read:org`, and `gist`" (`gh auth login --help`).
- **Single Redirects and the Worker.** Single Redirects are first in the "execution order of Rules features", and a terminating action is "executed immediately" (developers.cloudflare.com/rules/url-forwarding). "Requests handled by Workers will suppress Page Rules actions, but they will not suppress actions from modern Rules features" (rules/reference/page-rules-migration). But "Single Redirects require that the incoming traffic for the hostname ... is proxied by Cloudflare" (single-redirects/create-api). So the redirects survive the new Worker, and they don't survive the window with no proxied apex record. That is why the placeholder exists. `curl` on 2026-11-07: `jmap 308 https://ward.907.life/.well-known/jmap`, and the same for caldav and carddav.
- **The placeholder record.** "The attach writes a proxied AAAA at the apex pointing at 100::", and "records.mjs's carry-over gate already warns an admin whose apex carries an existing address record about this collision" (`hostname.mjs:12-15`). "`192.0.2.0` (A record) and `100::` (AAAA record) are reserved placeholder addresses for originless setups" (developers.cloudflare.com/workers/configuration/routing/custom-domains). Whether setup attaches over the placeholder is T4's read-only probe.
- **The mail check's tools.** `servers/scripts/tech-mail.sh`: "Read ward's technical mailbox with its read-only app password", with `list [N]` and `show ID`, and it "makes only Mailbox/get, Email/query, and Email/get calls". `dns.sh`: "Usage: dns.sh --check | --apply", using "the scoped CF_WS_SERVERS_TOKEN". The servers repo has no on-demand round trip: the monitor's inbound probe sends daily to `probe@probe.907.life` (`cloudflare/monitor/README.md`), and `tech-mail-probe.sh` accepts only probe.907.life mailboxes.
